# 架构说明 — 四六级词汇量检测

> 这份文档回答一个问题：**一个 2.18 MB 的单文件应用，为什么不用 React / Vue / TypeScript？**
> 答案不是"能力不足"，是三个硬约束下的取舍。

---

## 一、约束

| 约束 | 来源 | 后果 |
|---|---|---|
| **双击即用** | 交付形态就是"发一个 html 给评委" | 不能有构建期产物依赖、不能有 node_modules、不能有服务端渲染 |
| **断网可用** | 教育场景（机房、宿舍、考场） | 所有资源必须内联；任何 CDN 依赖都是死路 |
| **零运行时依赖** | 同上 + 体积 | 框架（React 45 KB gzip + 运行时开销）在这个体积预算里不划算 |

在这三条下面，框架带来的**收益**（组件复用、状态管理、类型安全）大部分可以用**更便宜的方式**拿到：
分层模块 + 单一状态对象 + JSDoc 类型 + 222 条断言。

---

## 二、模块划分与依赖方向

```
                    ┌─────────────────────────────┐
                    │  app.part1  基础层           │
                    │  状态 / 存储 / 路由 / 首页    │
                    │  （无内部依赖）               │
                    └──────────────┬──────────────┘
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
┌───────▼────────┐     ┌───────────▼──────────┐   ┌───────────▼─────────┐
│ app.part2 引擎  │     │ app.part3 视图/事件   │   │ app.part5 桌宠       │
│ 抽样/答题/判分  │     │ 结果/总览/设置        │   │ 物理/渲染            │
└───────┬────────┘     └───────────┬──────────┘   └───────────┬─────────┘
        │                          │                          │
        │              ┌───────────▼──────────┐               │
        └─────────────▶│ app.part4 AI 层       │◀──────────────┘
                       │ 面板 / SSE / 工具     │
                       └───────────┬──────────┘
                                   │
                       ┌───────────▼──────────┐
                       │ app.part9 练习层      │
                       │ 语境填空 / 听音辨词   │
                       └──────────────────────┘
```

**依赖方向是单向的**：视图层可以调引擎层，引擎层不回头调视图层。
所有跨层调用都通过 `A.xxx = function(){}` 挂到唯一的命名空间上，等价于"一个人人都能 import 的公共 API"。

| 层 | 文件 | 职责 | 不应该做的事 |
|---|---|---|---|
| 基础 | `part1` | 状态对象 `A.S`、localStorage、路由、词库、抽样、区间估计 | 不碰 DOM 渲染 |
| 引擎 | `part2` | 会话、出题、判分、揭示 | 不直接改路由 |
| 视图 | `part3` | 结果 / 总览 / 设置 / 事件代理 | 不做抽样计算 |
| AI | `part4` | 面板、SSE、工具调用可视化、语音输入 | 不产出任何数字 |
| 桌宠 | `part5` | 物理、渲染、Live2D 挂载 | 不读写业务状态（只读） |
| 练习 | `part9` | 语境填空、听音辨词 | 不污染阅读抽样 |

## 三、状态管理

**只有一个状态对象** `A.S`，结构固定、可序列化、整份存进 localStorage：

```js
A.S = {
  status:  { [wordIndex]: 0|1|2 },   // 逐词作答（2 bit/词）
  session: { ... } | null,           // 当前会话
  history: [ { ... } ],              // 归档轮次
  samples: [ { n, k, f, bands } ],   // 随机抽样（估词汇量用）
  settings: { ... },
  profiles: { ... }
}
```

**为什么不用响应式**：所有视图都是"状态 → 字符串"的纯函数（`A.viewX()`），
改完状态调 `A.render()` 重绘整块。这样没有隐式依赖、没有 diff 算法、没有订阅泄漏，
代价是重绘粒度粗——但页面只有 6 个，实测重绘 < 16 ms。

## 四、类型安全

没有 `.ts`，但有**类型检查**：

- `jsconfig.json` 开 `checkJs`
- 公共 API 用 JSDoc 标注参数与返回值
- `npx tsc --noEmit` 在提交前跑，**零错误**
- 运行时兜底：坐标、区间、评分任何一处出现 `NaN/Infinity` 立刻复位

这拿到了类型系统 80% 的收益（编辑器补全、参数校验、重构安全），不付构建期的代价。

---

## 五、构建

`build.js` 是一个 116 行的脚本，做四件事：读模板 → 内联 CSS/JS/词库/例句/立绘 → 写入 `index.html` → 打印体积。
**不写时间戳**，所以同样源码构建出同样字节（可 SHA256 比对）。

可选开关：

| 开关 | 作用 | 体积 |
|---|---|---|
| （默认） | 精简版 | 2.18 MB |
| `--with-key` | 内联作者 Key（演示用，不入库） | +1 KB |
| `--with-l2d` | 内联 Live2D 运行时与模型（活的小窗） | 8.0 MB |

## 六、性能

| 指标 | 实测 | 怎么测的 |
|---|---|---|
| 产物体积 | 2.18 MB（单文件，含 7,175 词 + 9,204 例句 + 10 张立绘） | `node build.js` 输出 |
| 首屏可交互 | 见 `docs/性能.md` | CDP 计时脚本 |
| 重绘耗时 | < 16 ms | `A.render()` 前后 `performance.now()` |
| 断言耗时 | 222 条 / 约 40 s（jsdom） | `npm test` |

**优化手段**：无框架、无虚拟 DOM、动效只动 `transform/opacity`（不触发 layout）、
词库与例句在构建期压成数组、图片压到 320 px 再内联。

## 七、测试

| 套件 | 条数 | 跑在哪 |
|---|---|---|
| `npm test`（冒烟） | 222 | jsdom，无浏览器 |
| `scripts/pet-test.mjs` | 40 | 真 Chrome（CDP） |
| `scripts/eval-rag.mjs` | 4 项指标 | Node |

冒烟测试是**行为断言**而不是快照：它点按钮、读 DOM、检查状态，
所以能抓到"结果页不显示词汇量"这种真缺陷（历史上真抓到过）。
