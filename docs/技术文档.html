1 项目概述

1.1 一句话定位

这是一个词汇量测量工具，不是背单词软件。用户花 3 分钟测出自己有多少词量、误差多大、薄弱在哪个词频段， 再决定背什么。背单词这件事仍然交给用户习惯的工具——本产品只负责"测准"和"开出补词清单"。

1.3 三个亮点

亮点具体是什么怎么验证
① 敢写误差结果永远是"数字 + 95% 区间 + 严格/折中两套口径"，题量由用户设定的目标精度决定，而不是固定 20 题首页大数字下方即区间；改目标精度看题量与区间宽度同时变化
② 结论可执行输出到"先补哪一段、哪些词、每天几个、几天补完"，并按「缺口 × 词频权重」排序报告页补词清单；每条可直接开始复测
③ 离线可用且 AI 不编数字单文件零依赖、断网可用；有 AI 时 AI 只解释数据，所有数字来自工具返回值屏蔽网络后跑 20 项断言；AI 面板看工具调用标签与依据面板

3.5 关键设计决策

决策理由
单文件交付学生真实环境是"发个文件就能用"，不装环境、不被墙、不怕链接失效；代价是词库要裁剪、体积要控在 2 MB 出头
零运行时依赖不引框架，避免"三年后依赖装不上"；统计与渲染都是手写，代码可读、可审计
AI 可选而非必需大模型要花钱、可能没网；把它做成"增强项"，没有它功能不残缺
数字由本机算模型的算术不可靠；所有统计量在浏览器内算完，模型只解释与排序
同一套引擎多端复用小程序版直接复用同一份引擎逻辑，用一致性测试保证逐字段相等，避免"两端数值不一样"

4 AI 技术方案

4.1 选型理由：AI 放在哪里、不放在哪里

AI 在这类教育工具里最容易犯两个错：一是替用户算数（算出好看但不准的数字），二是把它当必需品（没网就废）。 本项目的取舍是：统计与判定全部由确定性代码完成，AI 只负责把已经算好的数据翻译成行动建议。

环节由谁负责理由
抽样、区间估计、等级判定确定性代码可复现、可断言；同一份数据永远得出同一个数
题目排序、分组边界确定性代码FNV-1a 定序，保证不同设备抽到同一批词
"我该先补哪一段"的排序确定性代码给出候选缺口 × 词频权重是硬规则，模型不参与打分
解释、追问、把结论组织成计划大模型这类任务没有唯一答案，正适合语言模型
没有模型时的同等能力本地规则引擎保证"永远可用"，且在数据不足时敢说"下不了结论"

4.2 集成方式：三种形态与三档通路

档位触发条件能力
① 自带 Key用户在设置里填了自己的 API Key直连厂商、不限次数；Key 只存本机，导出备份时剔除
② 作者额度完成一次有效检测换取 1 次深度诊断（仅评委版内联了作者 Key）在线大模型；额度用尽自动降级
③ 本地方案以上都不满足、或没有后端确定性规则诊断，不联网、不限次、按真实数据出结论
A.aiTier = function () {
  if (A.S.userKey && A.S.userKey.key) return 'user';        // 用户自己付费，优先
  if (AUTHOR_KEY && A.aiQuota().left > 0) return 'author';   // 作者额度
  return 'local';                                            // 永远可用的兜底
};

额度是"完成检测换来的"，所以不能白给：同一轮、同口径只授予一次（用 kind:bank:round.startedAt 去重）， 整库检测要求测过 ≥100 词且覆盖 ≥95%，随机摸底要求 ≥80 题且达到目标精度。

4.3 Agent 与工具调用

后端是一个极简的函数调用循环：模型说"我要看频段数据"，服务端执行工具、把 JSON 结果回灌，直到模型给出回答或超过 3 轮。 关键是模型的输出永远不直接进界面数字位——界面上的数字来自工具返回值。

工具作用
get_profile取整体情况：词汇量、区间、双口径、覆盖率、四态统计
get_band_profile取七段词频掌握率与缺口
get_weak_words取没掌握 / 没测过的词清单
make_plan按每日可投入时间折算补词计划
get_examples按需检索真实例句（RAG）
get_round_diff取多轮差分：真学会 / 背了又忘 / 掉档
get_map_cell取词汇地图某一格的数据
get_quota取当前 AI 档位与剩余额度
suggest_actions动作工具：给出可点按钮（go / start / review / ask）
循环上限MAX_TOOL_ROUNDS = 3，避免模型无限取数
输出预算maxTokens = 1000；历史只带最近 6 条，控制成本
流式协议SSE 事件：mode / tool / delta / actions / done / error
可视化界面把"这次调了哪几个工具、拿到了什么"渲染成标签，回答下方可展开"本次发送给模型的数据"

4.4 提示工程：三条硬规矩

你是「四六级词汇量检测」工具里的诊断教练。规则：
1) 所有数字必须来自工具返回值，不许自己估算或编造；
2) 数据不足（样本 < 30 或覆盖率 < 95%）时直接说"样本太少，下不了结论"；
3) 掌握率只有两种口径：严格（只算认识）与折中（模糊算一半），不要自创第三种。

这三条不是写在文档里的愿望，而是被断言守着的：check-ai-link.mjs 会验证"动作按钮真的执行"、 "非法动作被拒绝"、"越界参数被规整"；check-ai-tiers.mjs 验证额度授予/扣减/下限保护。

4.5 轻量 RAG：例句是查出来的

语料Tatoeba 英中对照句 9,204 句（CC-BY 2.0 FR），覆盖 5,138 个词
索引构建期建"单词 → 候选句"倒排索引，并按可读性打分：词数接近 10–12、长度 60–80 字符、主语开头加分
运行期模型需要举例时调 get_examples，返回真实句子 + 中文译文 + 来源标注
为什么不用向量库向量方案要拖入几十 MB 权重，与"单文件 + 断网可用"直接冲突；本例的检索需求是精确命中单词，倒排索引足够且可解释

4.6 双向联动与动作白名单

图 → AI点频段条的「问」或 Shift + 点地图格子，问题文本里自动带上该块的真实数字，用户不用复述
AI → 图回答末尾给出可点按钮；点击后真的执行（复测该段 / 开一轮摸底 / 跳转页面）
安全边界模型输出被当作不可信输入：动作类型必须在白名单内，路由必须合法，target 夹到 {150,250,400}，频段夹到 0–6，问题文本截断到 120 字
按钮绑定每个按钮携带自己的动作对象（不是全局下标），避免"点了执行的是上一组的动作"

4.7 优化策略

策略做法与效果
降级链Agent（带工具）→ 直连模型（无工具）→ 本地规则。任一环失败都不弹错误框，而是在回答里说明当前形态
成本控制额度一次一授予；同一轮去重；历史截断 6 条；输出上限 1000 token；不需要 AI 的功能一律本地算
稳定性后端探活后再决定走 Agent 还是直连；SSE 断流有终态事件；超时与异常都落到本地规则兜底
可观测面板实时显示档位徽标（自带 Key / 作者额度剩几次 / 本地方案）与工具调用标签
密钥安全可选授权锁：Key 用 PBKDF2-SHA256（60 万次）+ AES-256-GCM 加密后内联，产物里无明文；解密只存内存

4.8 实测结果

联网主路径check-online-ai.mjs 7 项：回答来自模型、至少调用 1 个工具、带依据面板（实测 tool=3）
离线一致性同一份数据下，本地方案与在线诊断的数字部分完全一致（都来自同一批工具/同一套代码）
拒绝下结论样本不足时模型输出"样本太少"，check-ai-link.mjs 有对应断言

5 核心功能实现

5.1 检测的五个入口，共用一套统计内核

入口题量用途与口径
快速摸底约 80–130 题分层随机抽 100 词，得到带区间的词汇量估算；3–5 分钟
高精度约 210–340 题同一算法、目标误差 ±250 或 ±150，达标自动停
完整检测整库 4,540 词覆盖率 ≥95% 后转普查口径，逐词统计，不再外推；产出等级
分组检测每组 100 词可中断、可分工推进；只报进度，不外推词汇量
薄弱词复测按缺口词量把没掌握/没测过的词组成一轮，用于验证是否真的补上

5.2 词频分层抽样

词表按词频切七段（最高频 1k … 20k 以外），每段等比例抽。这样任何一个前缀都是一个合法的等比例样本， 因此可以边测边算精度、随时喊停。做法上还有两个细节：

稳定乱序用词自身的 FNV-1a 哈希定序：视觉上完全打乱，但每次打开、每台机器完全一致
交错抽取按各段词数比例交错出题，前 60 题就跨 5 个以上频段，避免连着考一串冷门词
效果同样 100 题：分层抽样区间 ±62 词，简单随机 ±91 词（约窄三成）

5.3 目标精度自适应停测

用户设目标半宽 h（±400 / ±250 / ±150），每次作答后重算当前区间半宽；半宽 ≤ h 且题量 ≥ 20 时提示可以收工。 题量是结果、不是设定——这是与"固定 20 题出结果"产品的本质区别。

5.4 区间估计的三层修正

se   = sqrt( max(p(1-p), 1e-6) / n ) * sqrt( (N-n) / (N-1) )    // Agresti-Coull 平滑 + 有限总体修正
half = 1.96 * se * N                                             // 折算回"词"的量纲
p'   = (k - f/k_opt) / (n - f/k_opt)                             // 四选一时先扣蒙对
vocab = p' * N,  CI = [ (p'-z·se)·N , (p'+z·se)·N ]
Agresti-Coull抽到全对或全错时区间不会塌成 0 宽的点
有限总体修正不放回抽样，乘 (N−n)/(N−1)；题量越接近整库，区间越窄，最后平滑过渡到普查
方差下限max(p(1-p), 1e-6)，杜绝"误差为零"的假精度

5.5 四选一的蒙对校正

四选一有 25% 蒙对概率，直接用正确率估计掌握率会系统性偏高。校正公式 (p − 1/k) / (1 − 1/k)， 并把"该样本是否为四选一模式"记进样本，两类模式分别估计、不混算。

5.9 词汇地图：182 格，图即入口

七段词频 × 26 首字母，颜色表示掌握率（绿 ≥80% / 黄 50–80% / 红 <50%），浓淡表示这一格测过多少。 点格子直接把这些缺口词组成一轮复测；Shift + 点则带着这一格的真实数字去问 AI。

5.10 回访卡：隔几天再打开，首页接上上次的结论

触发至少有 1 次随机抽样/整库实测，且距上次检测满 3 天；有未完成的检测时让位给「继续检测」
三行结论① 最该先补哪一段（target 与 weak 分开：高频三段还有洞就优先它们，冷门段最弱时如实说明不先补它）② 按每日时间折算补完天数 ③ 与上一轮相比是否超出 ±抽样误差
关闭「×」收起本次（不落盘）/「以后不再提醒」永久关闭（设置可重开）
成本全部本地计算，不联网、不消耗 AI 额度

5.11 自定义词书

支持 txt / csv / 粘贴导入，一行一个词，可选「词,释义」。导入前给出预览（总词数、命中内置词库、新增词条、 有释义比例、频段分布），并复用同一套引擎检测。边界写在界面上：自定义词书是有偏样本，只报"对这本书的掌握率"， 不能换算成词汇量。

5.12 每日可投入时间：一栏设置，四处文案

7.1 技术创新点

7.2 应用创新点

创新点用户看到的样子解决什么
A1 把误差当成一等公民结果永远是"数字 + 95% 区间 + 两套口径"，误差写在大数字旁边同类产品只给一个数，用户无法判断该不该信

附录 D　答辩常见追问

可能的问题一句话应答
你们这是背单词 App 吗？不是。我们只做测量与诊断：测准 + 开补词清单，背单词交给你习惯的工具。
测出来的数凭什么可信？误差写在数字旁边：分层抽样 + 有限总体修正 + 蒙对校正 + 双口径，抽样与估计有 201 条断言守着。
AI 具体做了什么？只做解释与规划：所有数字来自 8 个工具的返回值，模型不许自己算数；数据不足时它会拒绝下结论。
是向量 RAG 吗？不是。本地语料倒排索引 + 工具按需检索的轻量 RAG；向量方案会拖几十 MB 权重，毁掉单文件与断网可用。
断网能用吗？能。单文件双击即开，答题、进度、报告、本地方案全部离线可用。
为什么还要做小程序？同一套引擎换一种交付形态：小程序主包 1.56 MB，与网页版逐字段一致（1,302 + 34,310 条一致性断言）。
商业化怎么想？不卖课、不导流、不弹广告；AI 用你自己的 Key 或完成检测换来的额度，成本可见。
