一产品定义：我们卖的是"处方"

1.1 一句话定位

这不是一个"背单词 App"，而是一台词汇量测量仪 + 处方机： 测出你有多少词（带误差范围）→ 诊断差在哪（频段结构）→ 规划怎么补（具体词单 + 验收线）→ 复测验证（进步是真是假）。

产品边界用一句话划死：我们生产处方，不生产药。 背单词 App 的核心资产是内容与复习算法（重资产赛道）；我们的核心资产是测量与诊断的可信度。 所以规划环节的输出形态是可带走的任务单/词单，而不是在本应用里再造一个背词器—— 用户拿着这张单子去他用惯的任何产品背。

2.2 抽样的三个关键决定

分层词库按词频分 7 段（20k 以外 / 最高频 1k / 1k–2k / 2k–3k / 3k–5k / 5k–10k / 10k–20k）， 按各段真实占比交错抽取，低频段不会被高频段淹没
稳定乱序顺序来自单词自身的 FNV-1a 哈希（ordPos()），不是 Math.random()。 看起来随机，但每次打开、每台机器完全一致——否则"第 N 组"会指向另一批词，进度与跨轮对比全部失真
为什么不是字母序按字母序测就是一路 a、b、c 下去，既机械又能靠首字母猜词义，一组 100 词还会全挤在同一字母段

2.3 自适应停测

每答一题就重算一次区间半宽 half = z·√(p(1−p)/n)·√(1−n/N)， 当 half ≤ 目标精度 就提示"精度达标，可以收工"；否则给出"再答约 N 题"。 页面上实时显示当前精度与还需题量——让"测多少题"变成可解释的量，而不是拍脑袋。

2.5 频段剖面与"缺口 × 权重"排序

总掌握率会把高低频段平均掉——真正决定"读文章卡不卡"的是最高频那几段。所以诊断落到 7 段， 并对每段算两个量：缺口词数（测过还不会）与未测词数（压根不知道）。两者刻意分开： 把"整块没测"说成"缺口最大"是误导。

提升优先级 = 缺口词数 × 词频权重（权重取该段词频中位数的倒数，以最高频 1k 段 = 1 归一化）， 避免把最冷门的词排在最前。

2.10.3 稳定乱序的实现（FNV-1a）

// 抽题顺序由单词自身的哈希决定，不用 Math.random()
function ordPos(word) {
  var h = 2166136261;                       // FNV-1a 初始偏移
  for (var i = 0; i < word.length; i++) {
    h ^= word.charCodeAt(i);
    h = (h * 16777619) >>> 0;               // 32 位无符号乘法取模
  }
  return h;                                 // 同一个词在任何机器、任何时间都得到同一个位置
}
为什么要它看起来是乱序（每个词位置互不相关），但每次打开、每台机器完全一致。 否则"第 N 组"会指向另一批词，进度、跨轮对比、"继续上次"全部失真
为什么不用字母序一路 a、b、c 测下去，既机械又能靠首字母猜词义；一组 100 词还会全挤在同一字母段，地图会变成一条竖线
交错抽取按各频段真实占比从小数累加取词，所以一组 100 词里天然包含各频段的词，低频段不会被高频段淹没

2.10.4 estimate() 的完整实现

function estimate(tested, score, universe) {
  if (!tested) return null;
  var p   = score / tested;                                     // 样本掌握率
  var fpc = universe > 1 ? (universe - tested) / (universe - 1) : 1;  // 有限总体修正因子
  var se  = Math.sqrt(Math.max(p * (1 - p), 0.000001) / tested * fpc); // 标准误（下限保护防 0）
  return {
    p:     p,
    vocab: Math.round(p * universe),                             // 点估计
    lo:    Math.max(0,        Math.round((p - 1.96 * se) * universe)),
    hi:    Math.min(universe, Math.round((p + 1.96 * se) * universe))
  };
}
项取值/做法解决的问题
z 值1.9695% 置信水平
有限总体修正(N−n)/(N−1)不放回抽样；覆盖率越高，区间越窄
方差下限max(p(1−p), 1e−6)p=0 或 1 时标准误不为 0，避免区间塌成一个点
区间截断[0, N]不会算出负词数或超过词库总量
蒙对校正四选一：先按 1/4 猜测基线反推自评模式不扣，四选一模式扣；两者的数字不能混着比

注：本实现用 z=1.96 的正态近似（配合 FPC 与下限保护），并非严格意义的 Agresti-Coull 伪计数版本； 文档早期版本把它写成后者，这里更正。

2.11.1 每词 2 bit 的位图

// 0 = 未测，1 = 不认识，2 = 模糊，3 = 认识；每词占 2 bit，且起点落在偶数位，所以永不跨字节
function packStates() {
  var buf = new Uint8Array(Math.ceil(WORDS.length * 2 / 8));
  for (var i = 0; i < WORDS.length; i++) {
    var v = (A.getSt(i) === undefined ? 0 : A.getSt(i) + 1);
    var pos = i * 2;
    buf[pos >> 3] |= (v << (pos & 7)) & 0xff;

  return buf;                 // 存盘时再 base64
}

三行结论各自怎么来的（每一句都能追到数据）：

这一行算法
最该先补哪一段先取最近一次分层抽样的各段掌握率（样本 ≥3 词的段才参与）。weak = 全库最低的一段；target = 高频三段（1k / 1k-2k / 2k-3k）里只要还有洞就优先它们的那一段。缺口词数 = (1−掌握率) × 该段总词数

  • 焦点管理：入场页打开即聚焦「进入」；进入后焦点交还主内容区（#view tabindex=-1）；切页后同样
  • inert：入场页与模态打开期间，底层加 inert——键盘 Tab 与读屏都进不去不可见的界面
  • 对比度实测：辅助文字 4.83:1（≥4.5）、开关轨道 5.72:1（≥3），由浏览器测试里真实计算并断言
  • 减少动效：prefers-reduced-motion 下关掉全部动画，但入场页仍然存在、仍要点击（尊重设置，不替用户做决定）
  • 键盘全通：1/2/3/4 作答、空格/回车 下一题、退格 撤销、Esc 退出/关弹窗
  • 语义：图标按钮都有 aria-label，动态提示走 role="status" 的 live region

6.1 2.5D 的三种做法

透视倾斜鼠标位置 → rotateX/rotateY，perspective: 620px，转轴压在脚底，倾斜时脚不动只有上身摆
接地投影两层椭圆：贴脚的一小片最暗、外围一大圈更淡；跟着倾斜反方向横移、跟着离地高度缩小变淡
受光膜一条跟着倾斜转的斜向反光（soft-light），暗示光源在左上

工程细节：呼吸浮动与透视各占一层（同一元素的 transform 会互相覆盖）；脚底对齐用 canvas 扫 alpha 算出立绘底部约 1.6% 的透明留白并抵消；地面线、立绘盒底、导航上沿实测重合于同一像素。

6.2 行为清单

待在原地呼吸浮动（4.4s）+ 视线跟随（整体微倾 + 气泡反向视差）
自己溜达每 9–21 秒挑一个附近落点走过去，走时整体镜像（face-l）
活动范围只在右侧安全区（约屏宽 68% 之后）溜达，单次幅度 ≤170px；检测进行中不溜达；落在正文区会自己沿地面走回右下角
可拖动抓住即跟随，松手有重力、落地挤压回弹；双击回原位
悬空挣扎转轴从脚底挪到耳根；摆动角/落后量/拉伸挤压由指针速度驱动的二阶系统逐帧积分（起手甩出→急停回弹→松手余摆）；换不高兴的表情并喊一句；落地抖灰
说话气泡内容由真实数据决定（当前页面、掌握率、下一步建议），不是随机文案；长文只在文字区滚动
兜底每帧检查 NaN/死角驻留，异常自动复位；设置页有「叫回右下角」按钮；?pet=none 可整只关掉

6.3 气泡版式（一次返工的结果）

气泡 = 圆角卡片 + 尾巴，两者用 drop-shadow 合成同一个剪影，所以阴影和描边会顺着尾巴走， 而不是画成一个方块。文字与动作按钮分层：.pet-text 只放文字并独自滚动（4px 细滚动条， 溢出时底部 mask 渐隐），.pet-acts 固定贴底——按钮永远不会被滚走。按钮本身 27px 高、 双层渐变、hover 抬起 1px。

6.4 立绘

一套 MIT 授权的 512×512 全身立绘，构建期用 Chrome 的 canvas 重编码为 384×384 WebP（q0.62）， 10 张情绪图合计 349 KB 内联进产物——断网也有表情。一张都拿不到时桌宠退化成纯气泡助手，绝不画错形象。

十术语表与已知边界

10.1 术语

词频段按词在现代英语中的出现频率分的 7 个区间（最高频 1k … 20k 以外）
分层抽样先把总体按词频分组，再在各组内按真实占比抽取，可降低估计方差
置信区间对真值的区间估计；95% 表示重复抽样时约 95% 的区间会覆盖真值
有限总体修正不放回抽样时对方差的修正，覆盖率越高修正越强
蒙对率四选一时靠猜也能答对的概率 1/k，必须从掌握率里扣掉
严格 / 折中口径前者只把"认识"算掌握；后者把"模糊"按一半计入
整库实测（census）覆盖率达 95% 以上时直接逐词统计，不再做抽样估计
地基约束最高频段掌握率过低时对等级封顶
缺口 / 未测缺口 = 测过还不会（真正的洞）；未测 = 压根不知道（不构成结论）
逐词位图每词 2 bit 的状态压缩表示，用于跨轮差分
背了又忘上轮认识、这轮模糊或不认识的词，复习优先级最高
RAG检索增强生成：先查资料再作答。本项目是"轻量 RAG"（倒排索引 + 工具调用），不是向量检索

10.2 已知边界（如实写在界面上，也写在这里）

  • 不做背单词：规划输出的是一张可带走的词单，不在应用内再造一个背词器
  • 没有账号与云端同步：数据在浏览器里，换设备靠导出/导入。这是隐私与单文件交付的代价，是有意取舍
  • AI 不是向量 RAG：没有 embedding 与向量库；向量方案要拖入几十 MB 模型权重，会毁掉"单文件、断网可用"
  • 作者额度是本地计数：没有账号，清空存储即可重置——它只约束诚实用户，这一点不隐瞒
  • 自定义词书只报"对本书的掌握率"：词书是有偏样本，不能外推成词汇量
  • 发音依赖系统语音引擎：精简系统可能没声音，不影响答题
  • 窄屏（<820px）无桌宠：避免遮挡内容
  • 评委版内联了作者 Key：任何拿到该文件的人都能解出它。这是我们与用户共同接受的成本，比赛结束后应立即轮换

10.3附：答辩常见追问与应答

可能的追问一句话应答
你们这是背单词 App 吗？不是。我们生产处方、不生产药：测准 + 诊断 + 开补词单，背单词交给用户惯用的工具。
测出来准吗？凭什么？我们把误差写在结果旁边：分层抽样 + 有限总体修正 + 蒙对校正 + 双口径，并且抽样与估计有 195 条断言守着。
AI 具体做了什么？模型只做解释与规划，所有数字来自 8 个工具的返回值；数据不足时它会明确说"样本太少不能下结论"。
是向量 RAG 吗？不是。是「本地语料倒排索引 + 工具按需检索」的轻量 RAG；向量方案会拖几十 MB 权重，毁掉单文件 2 MB 与断网可用。
断网能用吗？能。单文件双击即开，答题、进度、报告、本地方案全部离线可用；AI 走不了时有确定性规则兜底。
数据会上传吗？逐题作答永不出本机；只上行汇总，而且每次回答下方可以展开看"本次发送给模型的数据"。
为什么不做账号/云同步？那会把数据搬到服务器，与"工具属于自己、无绑定"的方向相反。跨设备靠导出/导入。
为什么不做背单词/复习队列？那是重资产赛道（内容 + 复习算法），进去就是送；我们的壁垒是测量与诊断的可信度。
和市面测试比，差异在哪？三行：给不给误差、诊断到不到段、数据在谁手里。
提升是真的吗？跨轮逐词差分能区分"真学会 / 背了又忘 / 掉档"，不是拿两个点估计硬比。
作者额度为什么限次？作者 Key 有成本。完成一次有效检测换一次诊断；自带的 Key 则不限次，本地方案永远免费。
为什么不矩阵库的错？不敢：小词书测完就能 100% 覆盖，等于无限刷额度。所以授予条件里有 ≥100 词的下限。
你们的技术债在哪？字形、授权、口语维度。字形已用字体轮廓解决；Arial Black 授权需换开源重体；主动词汇维度还没做。
下一步做什么？口语/听力维度（产出性词汇）、IRT 自适应选题、构建期量化向量的语义检索、模拟校准实验。
