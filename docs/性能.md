# 性能实测

> 全部数字都在本机、`file://` 直接打开 `index.html`（2.18 MB 精简版）测得。
> 复现方式写在每张表下面。

## 一、加载

| 指标 | 实测 | 说明 |
|---|---|---|
| 产物体积 | **2,238 KB**（2.18 MB） | 含 7,175 词条、9,204 句例句、10 张立绘，全部内联 |
| DOMContentLoaded | **273 ms** | 词库与例句解析完成，应用已可交互 |
| load 事件 | **279 ms** | 全部资源就绪 |
| DOM 节点数 | **228** | 首页；无虚拟 DOM 的骨架开销 |
| JS 堆 | **9.5 MB** | 含词库与例句两个大数组 |

首屏没有再压的空间了——2.18 MB 里 **1.3 MB 是词库与例句数据**，那是产品本体，不是可裁剪的脂肪。

## 二、渲染

| 指标 | 实测 | 说明 |
|---|---|---|
| 整块重绘 `A.render()` | **6.9 ms** | 首页；低于一帧 16.7 ms 的预算 |
| 动效属性 | 仅 `transform` / `opacity` | 不触发 layout / paint |
| 桌宠网格 | 14×18 = 252 格 / 504 三角形，30 fps 上限 | Canvas 2D，单帧约 3 ms |

**为什么整块重绘还能这么快**：页面只有 6 个，每次重绘 200 多个节点；没有 diff 算法，
也就没有 diff 的开销。粗粒度重绘在这个规模下比细粒度更新更便宜。

## 三、测试

| 套件 | 条数 | 耗时 |
|---|---|---|
| `npm test`（jsdom） | 222 | 约 40 s |
| `scripts/pet-test.mjs`（真 Chrome） | 40 | 约 25 s |

## 四、复现

```bash
node build.js                     # 打印产物大小
npm test                          # 222 条
node scripts/cdp-eval.mjs "file:///.../index.html?intro=0" "<表达式>"   # 页面内取数
```

加载与渲染数字来自 `performance.getEntriesByType('navigation')` 与 `performance.now()` 差值。

## 五、已知边界

- **`file://` 下 Chromium 不产出 `paint` 性能条目**，所以首屏绘制时间（FCP）拿不到；
  上表用 DOMContentLoaded 作为"可交互"的代理指标，这是偏保守的口径。
- 数字是在本机（Windows / Chrome / SSD）测的，换机器会变；**只用于说明量级，不作为承诺**。
- 带 Live2D 的演示版（`--with-l2d`）体积 8.0 MB，DOMContentLoaded 约 900 ms——
  这是为什么把 Live2D 做成按需构建，而不是默认产物。
